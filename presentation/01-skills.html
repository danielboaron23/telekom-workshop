The problem

A button that goes nowhere

The workspace lets an agent find a customer, read their 360, configure an offer and run a five-step order. But an agent who searches and finds nobody hits a wall — there is no way to continue the call.

Create Customer buttonExists in Figma and in code — does nothing
Create Customer screenNo route, no frame, no spec
Project skills.cursor/skills/ does not exist yet

Note the problem statement. Not "agents need a create-customer screen" — that names the solution. "An agent who searched and found nobody has no way to continue." One of those you can solve several ways; the other tells you what to draw.

The method · /skill-creator

Why build a skill instead of writing a prompt

A prompt is advice you retype every time and that drifts every time. A skill is a checked-in folder of instructions, references and templates that loads itself when relevant — so the standard is the same on Monday as on Friday. Six steps, both times:

1

Clarify

A short batch of sharp questions. Never a wall — stop once the intent is clear.

2

Study the source

Read the linked repo for patterns worth distilling — not copying.

3

Read our repo

Routes, components, tokens, mock data, verification commands, dead ends.

4

Write

A lean SKILL.md that always loads, plus references/ and assets/ loaded only when needed.

5

Validate & package

quick_validate.py → package_skill.py → a shareable .skill.

6

Install

Project-scoped in .cursor/skills/, so it loads automatically in this repo.

Skill 01 · what makes it not generic

Three decisions worth stealing

the hard gate

Refuses to draft

No spec until the discovery questions are answered — and it names a thin answer instead of papering over it.

This is what turned it from a document generator into a thinking partner. It then did exactly this to me.

the invent gate

REUSE → COMPOSE → EXTEND → INVENT

Every element tagged, stop at the first that works, name the real file. INVENT costs a written justification and a Storybook story.

This is the mechanism that stops a second design system quietly appearing.

the scope cut

Every spec ends with a cut

Full spec / what ships in this repo / deferred.

No backend, no auth, fixed tokens, pixel-verified screens. A spec that ignores all four isn't buildable here.

The generic version of this skill says "write clear requirements". This one knows there is no error color token in our theme.

Skill 02 · the part worth showing

It tested the pipeline before designing it

Three cheap experiments came first. Each one changed the skill.

Skill 02 · what makes it not a screenshot dump

Three decisions worth stealing

the images

Download, never hotlink

Mobbin's image_url is a short-lived redirect. Hotlinking means a deck that breaks next week and a Figma paste that never worked.

One script solves both deliverables at once.

the honesty rule

Mobbin has no true competitors for us

It will never show you Amdocs or Dynamics. The skill says so out loud, offers proxy apps as adjacent precedent, and falls back to the web for behaviour.

Calling it "competitive analysis" would have been a lie.

the structure

The conclusion goes on slide two

Inherited from the analyst brain: lead with the answer.

A deck that saves its recommendation for the end is a screenshot gallery with suspense.

The skill got good because the agent tested before designing. Guessing would have produced a skill that hotlinks expiring images into a deck that doesn't match your slides.

Both prompts, one checklist

Seven parameters. Neither prompt had them all.

Parameter Skill 01 · the PM Skill 02 · the researcher Where it ends up biting
Triggers "every new feature and new screen" missing — nothing says when it runs It waits to be summoned instead of following the PRD
Tools · MCP missing — no tool named "connects to the Mobbin MCP" The PM reasons about screens it never opened
Success missing — a purpose, not a bar "HTML slides plus the Mobbin references" Nothing to aim at, so "thorough" becomes the goal
Method ·
the reference		 "Use lenny-skills as your reference for how strong PM skills are built" A bare URL, no verb A link is not an instruction

This is the part people get backwards. A longer prompt does not make a better skill. A prompt that walks the checklist does — and still ends with ask me questions. Note what's in neither one: no format, no sections, no tone. The structure came out of the conversation.
