folk

no results to create

"No results — We couldn't find any company matching “alex“." The primary action is a black button labelled Create "alex" — the searched term is carried into the action label itself, so the agent can see what will be created. Note also the left nav has a persistent "Duplicates 1" queue.

"No candidates, yet — Create a job to start receiving candidates." This is a first-run empty state, not a failed search, and the CTA points at a prerequisite rather than at creating the thing searched for. Useful contrast: do not conflate the two states.

05

Oyster

create — full page

"Add contact" as a full centred page with a "Back to points of contact" link. One "Primary contact" section: Full name, Email, Phone with country selector, Job title, then two scope fields. Identity first, everything else below.

06

Wave

create — full page

"New customer" full page, label-left layout. Exactly one required field, marked with * and explained ("Name of a business or person"); the primary contact block is visually grouped and entirely optional, with "+Add phone" / "Add contact" to grow it.

07

Zoom

create — modal over the list

"Add a New Contact" modal sitting directly over the contacts table, which stays visible behind it. Name is the only required field, followed by five separate phone fields (Office, Home, Mobile, Fax, Phone) — a fixed long form with no progressive disclosure. Save / Cancel bottom-right.

08

Skiff

create — inline panel

Contact editor opens as a panel beside the list. Shows Name, Email, Phone, Birthday — then a "+" menu offering Company, Job title, Address, Nickname, URL on demand. Progressive disclosure as an explicit control rather than a hidden section.

09

Proton

create — modal, fully progressive

"Create contact" modal where every group (Email addresses, Phone numbers, Addresses, Birthday, Notes, Other information) is a section with its own "Add" button. The form starts nearly empty. Maximum flexibility, maximum clicks — wrong trade for a timed task.

The duplicate 5

10

Navan

duplicate — offer the existing record

The create modal itself is split into two tabs: Add new traveler and Add existing traveler (with a search icon). A top-right toast reports "Email jdoe@content-mobbin.com is already registered" while the modal stays open and filled. The create surface offers the search the user should have done, and a collision does not destroy their typing.

11

Biosites

duplicate — inline field error

"An account with this email already exists." rendered as red helper text directly under the offending field, on blur, with the value left in place. Cheapest possible duplicate signal, and it points at exactly which field caused it — but it offers no way to reach the existing record.

The Leap

duplicate — inline field error

"has already been taken" under the email field. Same mechanism as Biosites, worse copy — the sentence has no subject, so it reads as a fragment.

13

Surfshark

duplicate — dead-end alert

Modal alert: "The Gmail account you're trying to add is already linked to a Surfshark account." The only action is "Got it". Blocks, explains nothing actionable, and offers no route to the existing account. Reject — this is the shape our duplicate handling must not take.

14

Square

duplicate — post-hoc merge queue

A dedicated "Review Duplicates" screen groups matched records and offers per-group Ignore / Merge, plus Merge All. Duplicates are treated as an ongoing data-quality job separate from creation — the same idea as folk's "Duplicates" nav item.

15

Airwallex

success — dedicated confirmation

"Your customer has been created", the new Customer ID shown as a copyable link, a card summarising the created record, and two actions: Create another (secondary) and View customer (primary). The closest reference in the whole set to our exact job.

16

HubSpot

success — modal with link out

"Success — 2 contacts were added to the new list: New Contacts ↗" over the list, with a single "Got it". Confirms the count and links to the created thing, then returns the operator to where they were.

Typeform

success — celebratory

"Your form has been published! 🎉" with next-step promo cards. Correct for a self-serve creator moment, wrong for an agent on their fortieth record of the day. Reject on tone.
