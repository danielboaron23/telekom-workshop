What to do with two directions

One of these ships. The other one is an argument.

Recommendation · ship

/catalog-v2 — inside the design system

It answers the brief with zero new tokens, keeps the agent inside one product, and can be adopted by repointing links rather than retraining anyone.

  • The chrome, tabs and rail are the ones agents already use
  • Nothing else in the app has to change for it to be correct
  • Every claim on it is covered by an assertion in the flow test
  • Remaining work is a product decision — which of the six entry points move
Recommendation · keep as a probe

/catalog-studio — off the design system

Not a shipping candidate — it's a deliberate control group. It shows what the catalog gains when the design system stops being a constraint, so the gains can be argued for one at a time.

  • Product photography instead of icon tiles — the biggest single readability win
  • Ratings and list prices give the agent something to say out loud on the call
  • A cart models multi-item orders that /offer can't express today
  • Each of those can be proposed to the design system with a running example

This is the real value of building both: the off-system version turns “our design system feels dated” into three specific, demonstrable requests. An opinion you can open in a browser is much harder to dismiss than a moodboard.
