Every element carries a tag · stop at the first that works

REUSE → COMPOSE → EXTEND → INVENT

The rule that kept a redesign from becoming a re-skin: you may not invent until you've proved the cheaper three don't work — and every INVENT owes a justification and a Storybook story.

REUSE
Most of it
AppShell, session tabs, WorkspaceHeader, buttons, fields, Icon, and every token in @theme.
COMPOSE
4 new
Customer strip, offer grid, Details panel, no-results — assembled from parts that already existed.
EXTEND
1 pattern
The offer card, in a new file. OfferCard.tsx is never imported, so v1 can't break.
INVENT
0
Zero new tokens. Zero new icons. The only new entity is the mock data file — and it lives beside the old one, not in it.

The one shared component touched: ProductsCard's Add new became a Link — same classes, same copy. That's the whole blast radius on existing code.

The section the skill is required to write about itself

Weak section: almost nobody will find it

What the PRD admits

One real entry point

Entry is Products → Add new on Customer 360, plus a direct URL. Four dashboard quick actions, the banner's Shop now, Find Customer's Shop, the wizard's back arrow and order-complete's Continue shopping all still open v1.

An agent who only uses quick actions will never see the new screen unless someone shows them the 360 path.

Why it shipped that way anyway

Repointing links is a product decision

Every one of those six links is a promise something else depends on — four of them are asserted in the flow test. Silently redirecting them would have made the safest part of the run the riskiest.

So the constraint stayed, and the gap got written down instead of hidden. The next run starts from a known problem, not a surprise.

Two open questions were answered the same way: the wizard's Back still returns to /catalog (accepted, out of scope), and the edited address is not persisted — session-only, exactly like Create Customer.
